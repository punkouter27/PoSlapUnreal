Mobile portrait: zero-scroll compaction and integrity (2026-10-26)

The HUD is one canvas layer (legacy AHUD::DrawHUD, authored at 540 × 960) plus one Slate layer (SSafeZone overlay, 1080-wide reference). Both carry their own safe-area and DPI arithmetic, so the menu sheet could run off the bottom of the screen and cover the corner anchors without anything noticing. This pass makes the sheet's height a measured budget, compacts every tab to fit inside it, and adds a layout audit that proves it at four phone aspects. Nothing scrolls: the sheet's content is clipped inside its budget, never cut by accident.

What changed

  1. Height budget. The sheet's content box is capped to a budget measured from the layer (SheetBudget, 78 % of the layer, less the safe inset, the anchor row and the padding) and clips whatever does not fit. The tab row sits outside the cap, so it is always reachable.
  2. The sheet sits above the corner anchors. It used to run to the screen edge and hide the build stamp (bottom-right) and the physics debug line (bottom-left) for as long as the menu was open. It now stops above that row, so all five anchors stay where the spec puts them.
  3. The judges table is one line instead of four, and the hand speed and the head snap share a line. The canvas panel behind the round/clock block is now sized to the text that is on it: the arena shows through instead of a 300 × 250 black box.
  4. The seven view badges share one row (TEL SCI XRAY SLOW LIVE COM DBG), each a wide thumb target, instead of two rows of 4 + 3.
  5. The ABOUT legend is a two-column grid and the roster card is cut to four lines. Before, both wrapped and the last line fell off the bottom of the screen.
  6. Touch targets. The roster tiles get a 44 dp minimum width; the badges fill their cell. The audit checks every target is at least 44 dp.
  7. A failed level load no longer bricks the menu. Travel() checks the package exists before opening it, and a level that does not open within 6 s gives the menu back — before, bTravelling stayed true forever and every control was dead.

The layout audit

-SlapLayoutTest opens the sheet, walks the three tabs and measures the laid-out widgets: the sheet against the layer, the tab content against the box it was given, the tab row, the five corner anchors and every touch target. It logs one line per tab and a summary, then quits. Sizes are in Slate units (dp); the absolute rects are used for the overlap checks. Run: UnrealEditor.exe PoSlapUnreal.uproject -windowed -ResX=540 -ResY=960 -nosound -SlapLayoutTest -game.

Checks

  • -SlapUiTest (the click test): PASS — 10 of 10 clicks right, a match ended (series 1-0) and the next began.
  • -SlapLayoutTest: 0 fails at four aspects, three tabs each.
  • The match, the brains and the physics are untouched: this is a display-only change.

Not done

  • The two renderers still keep separate safe-area arithmetic (the canvas uses Top/Bot, the Slate layer uses SSafeZone). They agree today because the canvas is written against the same numbers, but one authority for both would be better.
  • The safe area is only as good as the platform's report. A notch or a gesture bar in landscape, or a split screen, is not covered by the four aspects above.
  • The platform's safe inset is not faked in the test, so the desktop runs show a zero bottom inset. A phone run with a real nav bar is still to do (task E5).
  • The roster card truncates a long summary or brain list with an ellipsis. The full text is still in the card JSON.
